# Contributing

Use Issues for reproducible bugs and feature proposals. Search existing issues first. Explain the problem and expected behavior; an implementation plan is not required. Report vulnerabilities through the confidential process in [SECURITY.md](SECURITY.md).

Follow [the build instructions](docs/building.md) to install development dependencies. Run `npm run desktop:dev` for the Windows application; `npm run dev` is a browser preview with limited native functionality.

Before opening a pull request, run the checks listed in the build guide. Keep changes focused, describe the behavior and tests, and include screenshots for interface changes. Update documentation for changes to behavior, installation, settings or build commands. Use clear commit messages; Conventional Commits are optional.

Maintainers review scope, correctness and compatibility before merging. Review timing is not guaranteed. Discuss substantial behavior or dependency changes in an issue before implementing them. Contributions must be your own work or include compatible licensing and attribution. Never include personal audio, databases, credentials or private logs.
